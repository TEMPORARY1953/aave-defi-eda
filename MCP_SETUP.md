# Минимальная MCP-интеграция

В проекте есть бесплатный локальный сервер `mcp_server.py` на официальном Python SDK MCP.
Он предоставляет два инструмента: `get_analysis_summary` и `get_data_sources`.
Они читают только готовые результаты проекта. Сервер не нужен для выполнения ноутбука,
не обращается к кошелькам и не заменяет сбор данных из пяти источников.

## Установка и проверка

В PowerShell из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe verify_mcp.py
```

Проверка запускает сервер как дочерний процесс по stdio, выполняет `initialize`, `tools/list`
и два `tools/call`, после чего завершает соединение. Реальный ответ проверки сохраняется
в `data/mcp_verification.json`. Сначала выполните ноутбук, если `results_summary.json` ещё отсутствует.
В этой работе интеграция проверяется этим MCP-клиентом; подключение нового сервера к текущему
сеансу интерфейса Codex автоматически не заявляется.

## Подключение к клиенту

Для клиентов с форматом `mcpServers` используйте `mcp_config.example.json`, заменив оба пути
на абсолютные пути к Python из `.venv` и к `mcp_server.py`.

Для Codex CLI/IDE можно добавить в конфигурацию клиента следующий блок (замените пути):

```toml
[mcp_servers.aave_eda]
command = "C:/ABSOLUTE/PATH/TO/HW5/.venv/Scripts/python.exe"
args = ["C:/ABSOLUTE/PATH/TO/HW5/mcp_server.py"]
```

Существующую пользовательскую конфигурацию в ходе работы не изменяли. На другом компьютере
нужно самостоятельно добавить блок в используемый MCP-клиент и включить сервер.
Это необязательно для проверки EDA: `verify_mcp.py` уже проверяет взаимодействие по протоколу.

Основания: [официальный Python SDK MCP](https://github.com/modelcontextprotocol/python-sdk),
[документация MCP для Codex](https://developers.openai.com/codex/mcp).

## API и воспроизводимость

Основные запросы выполнены Python-скриптом `fetch_data.py`, без MCP-посредника. Это явно
отделено от проверенной MCP-интеграции для чтения результатов. Параметры, исходные ответы
и их SHA-256 лежат в `data/manifest.json`. Доступ к интернету для повторного анализа сохранённого
снимка не требуется. Ключи для свежей загрузки при необходимости берутся из `.env`.
